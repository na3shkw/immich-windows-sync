# 0009. ローカルでチェックサムを持たず、同期済みかどうかをパスで判定する

- ステータス: 承認済み
- 日付: 2026-07-04

## 背景

- 当初の設計（[0008](0008-assets-table-schema.md)）では、`assets` テーブルに `checksum` 列（`NOT NULL UNIQUE`）があった
- 目的は、ファイルの同一性をパスではなく中身で判定することだった
  - 移動・リネームされたファイルは、再アップロードせずにパスだけ更新する想定だった

## 決定

- `checksum` 列と関連コードを削除する
- 同期状態はファイルパスで管理する
- 未同期ファイルは「走査したファイルのうち、`status = 'success'` のレコードにパスがないもの」とする
  - 失敗したファイルと未登録のファイルは、どちらも再送の対象になる
- 内容が同じファイルの重複は、Immich 側の重複検出（SHA1 チェックサム）に任せる

## 結果

- アップロード前に、ファイル全体を読んでハッシュを計算する必要がなくなる
- ファイルを移動・リネームすると、新しいパスとして再度アップロードが試みられる
  - ただし Immich が `duplicate` と応答するため、アセットは重複しない
  - Immich のレスポンスは `immich_status` に記録される
- Immich 上でアセットを削除しても、ゴミ箱を完全に空にするまでは再アップロードが `duplicate` になる

## 経緯についての注記

- 削除したコミット（`9dc77d5`）には「チェックサム関連のコードを削除」とだけ書かれている
- 判断理由の記録は残っていない
- 当時の状況から推定される理由は次のとおり
  - `FindByChecksum` は同期フローで使われていなかった
    - 未同期ファイルの判定は、パスとステータスだけで行っていた
    - 「パスが変わったらパスだけ更新する」機能は、実装されないまま残っていた可能性が高い
  - 列を維持するには、全ファイルのハッシュ計算が必要になる
    - そのコストに見合わず、重複防止は Immich 側に任せれば足りる
