# 0007. 同期状態の保存に SQLite（modernc.org/sqlite）を使う

- ステータス: 承認済み
- 日付: 2026-03-07

## 背景

- どのファイルが同期済みか・失敗したかを、アプリの再起動をまたいで保持する必要がある
- 「単一実行ファイル・追加のインフラ不要」という要件がある

## 決定

- 組み込みの SQLite を使う
- ドライバは Pure Go 実装の `modernc.org/sqlite` を使う
- ORM は使わず、`database/sql` で生 SQL を書く

## 検討した選択肢

- **JSON ファイル**
  - 件数が増えると全件の読み書きになる
  - 条件検索もしにくい
- **bbolt（組み込み KV）**
  - パスでの 1 件検索なら十分
  - ただし、条件付きの検索が増える見込みがあった
    - ステータスでの絞り込み
    - 失敗ファイルの再送
  - そのため SQL の柔軟性を優先した
- **Badger / NutsDB**
  - bbolt と同様の理由で採らなかった
- **サーバー型 DB（MongoDB / Redis など）**
  - 別プロセスが必要で、要件に反する
  - 論点は「NoSQL か否か」より「組み込みか否か」だった
- **`mattn/go-sqlite3`**
  - CGO が必須になる
  - Windows でのビルドに MinGW が必要になる

## 結果

- CGO なしでビルドでき、単一バイナリで配布できる
- スキーマについては [0008](0008-assets-table-schema.md) を参照
