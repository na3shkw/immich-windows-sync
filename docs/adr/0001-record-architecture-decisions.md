# 0001. 設計判断を ADR として記録する

- ステータス: 承認済み
- 日付: 2026-09-23

## 背景

- これまでの設計判断は、次の場所に散らばっていた
  - 開発初期の設計メモ
  - エージェント向けの指示ファイル（`AGENTS.md` / `.claude/CLAUDE.md`）
- 同じ内容を複数のファイルで保守する必要があった
- なぜその判断をしたのか、今も有効なのかを後から追いにくかった

## 決定

- 設計判断は Michael Nygard 形式の Architecture Decision Record（ADR）として記録する
- `docs/adr/` に 1 判断 1 ファイルで置く
- 運用ルール
  - ファイル名は `NNNN-kebab-case-title.md` とする
  - 番号は連番で、再利用しない
  - 新しい ADR は [`0000-template.md`](0000-template.md) をコピーして作る
  - 判断を変えたときは、既存の ADR を書き換えずに新しい ADR を追加する
  - 置き換えられた ADR のステータスは「NNNN により置き換え」に更新する
  - `AGENTS.md` などには要点だけを書き、詳細は ADR へリンクする

## 結果

- 判断の理由と変遷が一か所にまとまり経緯を追えるようになる
- 2026-09 以前の判断は、当時の設計メモとコード・コミット履歴を突き合わせて後からまとめたものである
- 理由の記録が残っていない判断については、その旨を明記している
