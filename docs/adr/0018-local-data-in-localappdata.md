# 0018. DB と同期ログを %LOCALAPPDATA% 配下に移す

- ステータス: 承認済み
- 日付: 2026-09-23

## 背景

- [0016](0016-data-in-appdata.md) では、設定・DB・同期ログをすべて `%APPDATA%\immich-sync\`（Roaming）に置いていた
- DB と同期ログの中身は、この端末でのファイルパスと結びついている
  - 別の端末にローミングされても意味がない
  - むしろ別の端末では、存在しないパスを同期済みとして扱う原因になりうる
- 本番運用を始める前なので、今なら置き場所を変えても影響が小さい

## 決定

- 端末固有のデータは `%LOCALAPPDATA%\immich-sync\` に保存する
  - `syncdata.db`: 同期状態（[0008](0008-assets-table-schema.md)）
  - `sync.jsonl`: 同期ログ
- 設定 `config.json` は `%APPDATA%\immich-sync\`（Roaming）に残す
- フォルダ名は `appenv` の `appDirName` を Roaming と Local の両方で使う
  - dev ビルドでは `%LOCALAPPDATA%\immich-sync-dev\` になる（[0015](0015-dev-prod-build-tags.md)）
  - Local のフォルダのパスは `appenv.LocalAppDir()` 経由で取得する
- `%APPDATA%` にある既存の DB・同期ログは移行しない
  - 本番運用前なので、DB は作り直してよい
  - 古いファイルは手動で削除する

## 検討した選択肢

- **起動時に古い DB を自動で新しい場所へ移す**
  - 移さないと、全ファイルが未同期として扱われ、再スキャンが走る
  - しかし本番運用前で移すべきデータがないため、移行コードを持ち続ける理由がない
- **設定も `%LOCALAPPDATA%` に移し、1 つのフォルダにまとめる**
  - 設定の中身（Immich の URL・API キー）は端末に依存しないため、Roaming のままにした
  - ただし監視対象フォルダのパスは端末に依存する。複数端末で使う場合は改めて検討する
- **DB だけ移し、同期ログは `%APPDATA%` に残す**
  - 同期ログもこの端末での同期結果なので、DB と同じ扱いにした

## 結果

- 端末固有のデータがローミングされなくなる
- アプリのデータが `%APPDATA%` と `%LOCALAPPDATA%` の 2 か所に分かれ、ユーザーが探す場所が増える
- 置き場所を変えると、初回起動時に全ファイルの再スキャンが走る
